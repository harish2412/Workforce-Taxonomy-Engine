# Workforce Taxonomy Engine

Capstone project, Taxonomy of Work, Skill Taxonomy track.
Building a skill taxonomy from job postings, validated against ESCO.

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

Copy `.env.example` to `.env` and fill in whichever API keys you use.

## Data

- `data/raw/sample_postings.csv` — 400 job posting sample, 19 job families
- `data/extracted/skill_statements_sample.csv` — 13,958 extracted skill statements,
  with a `confidence` column (high / medium / low)
- `data/esco/skills_en.csv` — ESCO reference skill list (~13,960 skills)
- `data/esco/skillsHierarchy_en.csv` — ESCO's own multi-level hierarchy, for
  Sprint 4 evaluation
- `data/golden_set/golden_dataset.xlsx` — 100 human-reviewed job postings with
  verified skill lists, the ground truth for precision/recall evaluation
- `data/golden_set/rule_nlp_extraction.xlsx` — Rule+NLP output on those same
  100 postings
- `data/golden_set/gemini_extraction.csv` — Gemini LLM extraction on the same
  100 postings, for comparison (scored higher on precision/recall in testing,
  but the pipeline below still runs on Rule+NLP output — switching is an open
  item, not yet done)

All of the above are tracked in git. Everything in `data/processed/` and
`data/raw/rule_nlp_handoff/` is **not** tracked (regenerated by the pipeline,
or too large) — see "Getting the large files" below.

## Pipeline (src/), run in this order

| Script | Sprint | What it does | Needs GPU? |
|---|---|---|---|
| `clean_statements.py` | 3 | filters to high/medium confidence, dedupes → `unique_statements.csv` (5,412) | No |
| `clean_unique_statements.py` | 3 | two-pass cleaning: confirmed noise patterns + manually-reviewed bare-word judgment → `unique_statements_cleaned.csv` (4,974) | No |
| `embed.py` | 3 | embeds the **cleaned** statements with Qwen3-Embedding-8B → `embeddings.npy` (4,974 × 4,096) | **Yes** |
| `cluster_both.py` | 3 | k-means at k=30 and k=80, saved separately → `cluster_labels_k30.npy`, `cluster_labels_k80.npy` | No |
| `inspect_clusters.py` | 3 | prints real sample statements per cluster, for manually naming them | No |
| `stability.py` | 3 | multi-seed stability check (Adjusted Rand Index); set `BEST_K` to 30 or 80 | No |
| `visualize_highlighted.py` | 3 | produces both a full-color map and a named/highlighted map for a given k — run as `python src/visualize_highlighted.py 30` or `80` | No (but needs `embeddings.npy`) |
| `cluster_validation.py` | 4 (optional) | ESCO-category validation of cluster quality, needs manual labeling of a 150-statement sample (`bare_words_for_review.csv`-style workflow) | No |

Each step reads the previous step's output from `data/processed/`. Only
`embed.py` needs a GPU — everything else, including both clustering runs and
both visualizations, runs fine on a laptop CPU once `embeddings.npy` exists.

## Embedding model

`Qwen/Qwen3-Embedding-8B`, run on an Explorer GPU node (V100 or better,
32GB+ memory). `MODEL_NAME` must match in both `src/embed.py` and `app.py` —
the demo loads embeddings generated by whichever model `embed.py` last used.
An earlier baseline used `all-MiniLM-L6-v2` on CPU; that's superseded.

## Where we landed on k

Tested k=20, 30, 50, and 80 on the final cleaned corpus. No single k has been
chosen yet — it's a real tradeoff, not an oversight:

| k | Silhouette (separation) | Stability (avg ARI) |
|---|---|---|
| 20 | 0.0344 | not tested |
| 30 | 0.0353 | **0.596** |
| 50 | 0.0401 | not tested |
| 80 | **0.0431** | 0.461 |

k=30 gives broader, more consistent categories. k=80 separates more cleanly
but reshuffles more between reruns. Both `cluster_labels_k30.npy` and
`cluster_labels_k80.npy` exist so either can be used — `app.py`'s `LABELS_PATH`
constant controls which one the live demo reads.

## Live demo

```powershell
streamlit run app.py
```

Type any skill phrase, see which cluster it's assigned to and what else is in
that cluster, or browse any cluster directly from the sidebar. Needs the real
Qwen model loaded, so **this specific step needs a GPU** — run it on an
Explorer compute node, not a laptop. (A `fake_encode` stub is commented out at
the top of `embed_query()` for testing the frontend layout only, with no GPU;
swap the two lines back if you need that.)

## Getting the large files (not in git)

`embeddings.npy`, `cluster_labels_k30.npy`, `cluster_labels_k80.npy`, and
`unique_statements_cleaned.csv` are not committed — the first is 85MB+ and
the rest regenerate from it. Two ways to get a working copy of
`data/processed/`:

1. **Regenerate it yourself** — run the pipeline table above in order,
   `embed.py` needs a GPU session.
2. **Get it from a teammate** — ask for a zip of `data/processed/` directly
   (Drive, Slack, whatever's easiest) rather than regenerating from scratch
   every time.

## Known open items (Sprint 4)

- Stability hasn't been tested for k=20 or k=50 — only 30 and 80.
- The pipeline still clusters Rule+NLP's extraction output, even though
  Gemini's output scored higher on precision and recall in evaluation.
- ESCO-category validation (150-statement sample) is built but not yet
  labeled by two independent reviewers.
